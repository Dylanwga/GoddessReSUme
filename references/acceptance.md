# 验收与返修

按实际产物检查本轮要求。内容依据来自用户材料，格式依据来自 [版式规范](style-spec.md)。执行过流程、保存成功或 XML 中存在某个属性，均不能单独证明成稿合格。

## 验收范围与证据

完整生成检查全部内容、对象及渲染页面；局部编辑检查改动、受影响邻近区域与指定保留区域；仅交付文案时不执行文档结构和视觉项。只检查本轮适用要求，不借验收扩大修改范围。

工作笔记中记录结论和证据即可：**通过**表示有实际证据；**不通过**表示已定位偏差；**未验证**表示缺少必要条件；**不适用**表示本轮无需检查。事实对应证明内容来源，OOXML 证明结构，渲染证明显示，必要的目标应用操作证明交互；这些证据不能互相替代。

## 一、内容

| 检查对象 | 通过标准 |
| --- | --- |
| 来源与覆盖 | 使用正确底稿；机构、日期、项目、技术、成果与论文有逐项去向。早期内容未覆盖后续手改，改写未改变事实。 |
| Owner 与贡献 | 已确认 Owner 的负责范围在职责中明确；参与、模块负责、项目身份与具体个人行动分别有依据。仓库 README 或架构文档未被当作个人交付证明。 |
| 项目背景 | 采用完整项目结构时，有可单独识别的背景内容单元，说明场景、问题或目标，与职责不重复。短条目或局部文案按其范围处理。 |
| 技术表达与结果 | 技术与任务关系清楚，不靠术语堆砌或重复拆句填篇幅；指标、比较基线、部署、论文状态与作者顺序符合来源。 |
| 教育介绍 | 有材料时合理展示导师、方向、活动或荣誉；用户要求的填写位置已保留。普通成稿没有意外遗留的模板占位。 |
| 可选技术栈 | 核心技术逐项能关联用户材料或项目来源；没有将依赖清单全部搬入，未把项目采用某技术等同个人“精通”。 |
| 字段与特殊内容 | 联系信息、主页目标、公式、上下标、共同作者标记和链接显示文字准确。缺失资料没有虚构；用户要求预留的字段不被误判为遗漏。 |

文字字面不同不自动代表遗漏，相同也不代表语义与责任正确。内容不通过返回 [内容流程](workflow-content.md)，必要时先恢复正确底稿。

## 二、对象与格式

| 检查对象 | 通过标准与典型失败 |
| --- | --- |
| 包与关系 | ZIP/XML 可解析，内容类型和关系目标有效；按所属部件核对图片、超链接和唯一对象 ID。 |
| 字体与层级 | 可见文字、超链接、编号均符合规范。解析直接格式与必要继承，检查中文、西文、字号及强调，不只看 Normal 样式。 |
| 段落与文本框 | 每个逻辑段落、项目符号和论文条目各有独立文字框；正文不藏在大表格、截图、整页组或多段落共框中。自然换行无需拆框。 |
| 栏目组 | 标题与正文等宽的原生填色横线处于同一局部组；项目小标题没有误加栏目横线。仅有段落下边框、文字下划线或下划线字符不符合默认组件结构。 |
| 机构组 | 底色矩形没有文字；图标是独立图片；文字框透明、垂直居中，机构图片不在文字段落内。组内坐标、尺寸与字段制表位有效，各子对象可编辑且整条可共同移动。 |
| 项目仓库 | 仓库归属正确项目；标题、图标和链接同一文本框，使用右对齐制表位，目标真实有效。不能将项目仓库误排为页首个人主页。 |
| 原生编号 | `w:numPr` 指向有效定义，符号字体、级别、悬挂与续行缩进正确；手打圆点不替代要求的列表。 |
| 图标与主题 | 对照任务图标清单逐项检查身份与放置位置，图片已嵌入；不能由媒体总数判断覆盖。主题来自选定经历，各色用途一致，品牌图标保留原色与比例。 |
| 联系信息与链接 | 每个实际提供字段配适当图标，显示文字与真实目标对应；未继承其他平台的链接。仅有账号时不虚构 URL。 |
| 局部编辑保留项 | 未涉及的内容、位置、公式、字段、链接、编号和修订状态保持；已有兼容分支同步更新，未为保存成功清空未知部件。 |

结构问题返回 [组件构建](construction.md) 或 [Word 精修](word-editing.md)；图标缺项返回 [获取流程](icons.md)。不能用调高文本框掩盖错误的分层方式。

### 只读结构清点

从 skill 根目录运行，报告保存在本次任务目录：

```sh
python scripts/docx_inventory.py after.docx > inventory.json
python scripts/docx_inventory.py before.docx --compare after.docx > diff.json
```

清点工具仅依赖标准库，提取文字、公式、符号、关系、图片、文本框、锚点和原生组信息。它选择一个受支持的 `AlternateContent` 分支，按保留插入、排除删除的视图统计，不修改文档或接受修订。目标应用可能采用不同显示视图，仍需检查实际画面。

使用 `structure_summary` 定位多个逻辑段落共框、正文脱离文本框及显式换行；结合 `native_groups`、`drawing_objects` 和 `drawing_structure_summary` 核对分层、填色和垂直对齐。比较报告中的段落、字符、链接和媒体变化是定位线索，不是自动的语义验收。框数与媒体数没有固定合格值。

工具不会证明实际字体、文本溢出、视觉居中、链接在目标应用中的交互或对象拖动效果。需要时在工作副本中选取和移动局部组，确认文字、背景及图标既可分别编辑，又可整体移动。

## 三、视觉与可用性

先渲染最终保存版本：完整任务打开**全部页面**检查；局部任务检查全部受影响页，分页变化时覆盖后续页面。环境提供 documents 技能时使用其 `render_docx.py`；否则使用可用的可靠渲染器并记录环境和字体限制。不要用源文本检查替代页面检查。

| 检查对象 | 通过标准 |
| --- | --- |
| 可见性与安全边界 | 没有裁切、文字互压、缺字、图标遮挡或超出页底安全区；估算高度及 `autoFit` 均以实际画面验证。 |
| 栏目横线 | 每条应有横线的栏目都清楚可见，贯穿正文列，贴近标题下缘但不穿字；各栏目的左右边界一致。 |
| 机构居中 | 字形在底色条带内上下留白协调，与独立图标的视觉中心相容；不能因 `anchor=ctr` 已设置就判定通过。 |
| 项目标题与链接 | 同行、基线协调、链接右边界正确，长标题与链接不相撞，点击目标正确。 |
| 内容密度 | 同级文字间隔紧凑一致；单行段落没有无故保留多行空白，项目与栏目之间有清楚层级。 |
| 页首与可选内容 | 联系图标与分隔符清楚，技术栈在联系信息下方且不过密，照片不遮挡；教育填写位符合用户要求。 |
| 分页与一致性 | 没有孤立栏目或项目标题；同级字体、编号、色彩和对齐一致。页数由内容决定。 |
| 保留区域 | 局部任务用同环境前后渲染核对未涉及区域及必要位移，不能以整页重建覆盖用户手改。 |

### 目标应用显示差异

用户报告 Word 中缺线、偏位或裁切时，该反馈是必须处理的具体缺陷。检查目标应用或取得可用的目标显示证据；需要时调整对象实现后重新验证，不能继续用另一渲染器的正常预览宣称问题不存在。无法验证目标应用时标为未验证，说明已做的结构和渲染检查，不宣称已完成该应用验证。

## 返修与交付

内容问题回到来源与撰写，结构问题回到组件，视觉问题回到几何、字体和分页。反复出现同一显示缺陷时重新检查实现方式，避免只增加框高、空格或固定偏移。修正后检查受影响项与页面；新变化造成的相邻布局也要复查。

交付最新成稿及必要的缺项说明。验收 JSON、截图与缓存属于任务工作资料，不自动加入交付物。维护 skill 时，组件、虚构样例和预览必须来自同一版规则，并用独立的虚构任务检验实际行为；候选人的正式简历不进入仓库。
