# 独立验收与返修

验收检查实际产物是否满足本轮请求，不以执行过流程、脚本退出成功或文件能够打开代替通过。内容依据来自本轮确认的材料；版式参数统一引用 [版式规范](style-spec.md)，不在验收文件另设字号、尺寸或配色。用户指定的新样式和保留范围优先。

## 范围、证据与状态

- **整份生成或优化**：检查全部内容单元、适用的对象结构与全部渲染页面。
- **局部编辑**：检查改动、必要的邻近调整、指定保留区域，以及关系、页数等可能受影响的部分。不借验收重写未授权区域，也不声称原有问题已全篇修好。
- **只交替换文案**：执行内容验收；没有生成文件时，文档结构与视觉项记为不适用。

工作笔记中为适用项记录结论、证据位置和必要的返修步骤即可，无需额外交付一份验收表，也不强制由另一个模型检查。记录应能区分：

| 状态 | 含义 |
| --- | --- |
| 通过 | 已检查实际产物，有足够证据满足本轮要求。 |
| 不通过 | 已发现具体偏差，需要修正；附内容单元、对象或页号以便定位。 |
| 未验证 | 缺少工具、目标字体、来源或其他必要条件，尚不能判断。未报错不等于通过。 |
| 不适用 | 本轮明确不涉及该项，或用户要求使该项不再适用；简记原因。 |

同一检查可有多种证据：内容对应表证明事实覆盖，OOXML 证明对象与属性，渲染证明显示结果。三者不能相互替代。

## 一、内容验收

| 验收项 | 证据与判断方法 | 不通过返回 |
| --- | --- | --- |
| 来源与修改范围 | 确认使用用户指定的最新底稿及权威文字来源；将新稿与保留区域逐项对应，早期版本未覆盖后续手改。 | [内容撰写](workflow-content.md) 的来源核对；涉及错误底稿时先恢复正确版本。 |
| 事实完整 | 对照原始事实与新版内容单元，逐项核对机构抬头、时间、项目、职责、技术、成果及论文；删除或合并有本轮需求或合理改写依据。 | 内容撰写的事实提取与组织。 |
| Owner 与责任边界 | 对照用户提供的个人行动与负责范围；确认的 Owner 在职责句中明确体现，参与或模块负责没有升级为全项目负责。 | 内容撰写的责任确认与改写。 |
| 专业化与可读性 | 在材料支持范围内说明做什么、为何做、本人如何做和实际结果；不强求每项具备所有维度。技术与业务关系清楚，不靠术语堆砌或重复拆句增加篇幅。 | 内容撰写的组织与改写。 |
| 指标与结论 | 核对指标口径、比较基线、论文状态、作者顺序、部署与业务结果；来源未支持的数值、因果和落地结论不得新增。 | 内容撰写的事实核对与措辞。 |
| 缺失字段 | 没有虚构日期、主页、照片或统计；可省略字段已省略，需要确认的信息已明确处理。最终稿不残留无效链接标签、待补日期或示例占位文字，用户明确要求填空模板时除外。 | 内容撰写的缺项处理；页首空间回到 [排版流程](workflow-layout.md)。 |
| 特殊内容 | 公式、上下标、共同作者标记、链接显示文字及必要字段语义完整；换段和排序未改变含义。 | 内容撰写；对象损失转 [Word 精修](word-editing.md)。 |

文本字面不同不自动判为遗漏，文本字面相同也不证明责任范围、语义或完整性正确。无法取得原始经历依据时，明确未能验证的事实项，不自行认证 Owner 或新增成果。

## 二、格式与结构验收

| 验收项 | 证据与判断方法 | 不通过返回 |
| --- | --- | --- |
| 文件完整与关系 | ZIP/XML 可解析，内容类型与关系目标正确；图片和超链接的关系按所属部件核对，对象标识无意外冲突。 | [Word 精修](word-editing.md) 的 OOXML 编辑。 |
| 字体与文字层级 | 对照版式规范逐类检查可见文字、超链接内 runs、编号定义；解析直接属性与必要继承，确认中文、西文、字号和强调均正确，主题字体未覆盖显式设置。 | [构建组件](construction.md) 或局部字体修改。 |
| 独立文本框 | 内容单元与原生文本框逐项对应；标题、逻辑段落、各级条目及论文题录按规范分别成框。检查普通正文、表格、多个段落共框及手动换行，不只检查框总数。 | 构建组件或 Word 精修的拆框步骤。 |
| 可独立移动 | 检查组结构与原生对象类型；正文未锁在整页或整段经历的大组中，图像或表格未替代要求的可编辑文本框。需要时在工作副本中选取、移动验证。 | 构建组件或 Word 精修的对象组织。 |
| 栏目标题横线 | 存在规定的原生横线或段落下边框，随标题移动；未以标题下划线、大量下划线字符或带下划线空格模拟。实际宽度和位置另做视觉验收。 | 构建组件的栏目标题。 |
| 机构条带 | 背景、图标、机构和其他字段作为一条可整体移动的条带；字段样式遵循规范，日期使用真实对齐机制，未拆成互不关联的对象或用连续空格凑列。 | 构建组件的机构条带。 |
| 列表层级 | 条目具有原生 `w:numPr`、有效编号定义、正确字符字体和悬挂缩进；正文中手打圆点不替代原生编号。 | 构建组件或 Word 精修的编号。 |
| 图标覆盖与嵌入 | 将任务图标清单逐项对照实际放置位置，确认身份匹配、已嵌入且部件关系有效；不能凭媒体总数非零断言所有位置都有图标。图标不依赖外部文件或远程加载。 | [图标获取](icons.md) 的检索、核验或嵌入。 |
| 主题与品牌 | 主题来源对应选定经历，栏目、项目和浅色条带使用同一套颜色关系；其他品牌图标保留原色。局部任务没有擅自重选全篇主题。 | 图标获取与排版流程的配色。 |
| 联系方式与链接 | 每个实际提供的联系字段有正确图标；邮箱、电话及主页链接有准确目标，与显示文字对应，复制图标未继承别的平台链接。仅有即时通讯账号时保留账号，不编造 URL；真实链接的关系有效且目标非示例或占位值。 | 内容缺项处理、图标嵌入或 Word 精修的关系编辑。 |
| 原有对象与兼容分支 | 局部任务保留未涉及的运行格式、公式、字段、修订与批注；修改对象的现代与兼容表示保持一致，未清空未知部件以求保存成功。 | Word 精修的范围定位与兼容分支处理。 |

### 清点工具与证据

`scripts/docx_inventory.py` 是标准库只读清点工具，报告段落文字、公式文本、符号、链接、媒体、文本框及部分几何信息；可辅助比较空白归一化后的段落增减和字符计数。它按部件解析关系，区分嵌套文本框与外层宿主段落，避免重复统计。

从 skill 根目录运行：

```sh
python scripts/docx_inventory.py before.docx --compare after.docx > diff.json
python scripts/docx_inventory.py after.docx > inventory.json
```

使用可用的 Python 运行时；输入与输出报告放任务工作目录，以上文件名只是用法示意。

**分支与修订视图：** 工具为 `mc:AlternateContent` 选择一个受支持的有效分支，避免把 `Choice` 与 `Fallback` 的同一内容重复计数。它读取保留插入、排除删除的视图，仅在内存中用于清点，不接受或修改文档修订。这个视图不自动等于用户要求的修订显示方式，也不保证与所有目标渲染器的选择一致；仍需检查实际显示和被修改的兼容分支。

**`textboxes`：** 每个 `w:txbxContent` 对应一个 `textbox_id`，同组内的两个文本框仍分别计数。该 ID 是本次清点的定位标识，不是跨版本稳定的 OOXML 对象 ID。每框的 `paragraph_indices` 指向报告 `paragraphs` 数组中的零基索引，并与段落的 `context.textbox_id` 对应；空白段落不计入这些非空统计。`nonempty_paragraph_count` 和 `line_break_paragraph_indices` 可定位多段共框和显式换行。

**`structure_summary`：**

| 字段 | 用途与解释 |
| --- | --- |
| `textbox_count` / `nonempty_textbox_count` | 全部框数与含非空文本的框数；照片、图标或背景空框可能影响总数，不能据此判断拆分合格。 |
| `textbox_nonempty_paragraph_count` | 文本框中的非空段落总数，用于与内容单元核对。 |
| `multi_paragraph_textbox_count` / `multi_paragraph_textbox_ids` | 定位一个框内有多个非空段落的候选问题。 |
| `line_break_paragraph_count` / `line_break_paragraph_indices` | 定位 `w:br`、`w:cr` 等显式换行；自动折行不产生新段落，换行存在本身也不一定是错误。 |
| `body_nonempty_paragraph_count` / `body_paragraph_indices` | 文档主体中不属于文本框的非空段落，包含表格正文；检查要求转换的内容是否遗留。 |
| `ordinary_body_nonempty_paragraph_count` / `ordinary_body_paragraph_indices` | 再排除表格后的普通主体段落；上述两类主体计数均不含页眉、页脚与注释部分。 |

这些数据是定位线索，不能直接生成通过结论。一个框即使只有一个段落，也可能用手动换行拼接多个条目；多个框也可能被锁在一个大组。按实际内容单元判断，不要求所有简历与脱敏样例有相同框数。

按任务解释比较结果：

- **只改格式**：新增、删除应仅来自预期标签、空白或换段调整；字面一致仍需核对链接关系和显示位置。
- **拆段或重排**：段落计数变化可以合理，字符计数只辅助发现遗漏，不能证明语义正确。
- **正文改写**：逐项核对原始事实与新表述，不以机械字面相同为目标。
- **PDF 为内容依据**：另行提取并目视核对 PDF；此脚本只处理 DOCX，不证明与 PDF 一致。

工具不会计算 Word 页面流、实际文字溢出、有效字体、编号显示文本或动态字段结果，也不能证明对象独立可移动。复杂公式、符号、隐藏文字、分组和外部关系仍需针对性检查。字体、编号与条带检查需要额外读取相应 OOXML；显示是否正确必须由渲染补证。

## 三、视觉与可用性验收

在目标字体可用的环境中使用文档渲染工具。若有 documents 技能，遵循其渲染和交付约定；通过环境依赖发现运行时，不在 skill 中写死某台机器路径。完整任务查看每一页实际图像，不只查看第一页或提取出的文字。

| 验收项 | 证据与判断方法 | 不通过返回 |
| --- | --- | --- |
| 字体与字符显示 | 查看中英混排、技术符号、公式及项目符号；结合字体匹配结果排除替代和缺字。OOXML 声明正确但环境替代时仍未完成验证。 | 排版流程的环境检查，随后重渲染；不因环境缺字体擅改正文。 |
| 完整可见 | 逐页检查最后一行、文本框边界、栏目前后及页尾，无裁切、遮挡、重叠或页外内容；正文框及实际文字遵守规范中的页底安全边界，仅未越过纸边不算通过。固定高度与自动适应设置都不是保证。 | 排版流程的框高、间距与分页。 |
| 层级与对齐 | 对照版式规范及脱敏预览，确认栏目横线覆盖正文宽度、条带边界统一、日期靠右、同级缩进及续行对齐正确。 | 构建组件或排版流程的对齐调整。 |
| 图标与页首 | 图标比例、视觉尺寸、基线和文字间隔协调，没有透明留白造成的假性缩小；照片不遮挡文字；单行要求确实未自动换行。 | 图标获取的资产核验或排版流程的页首布局。 |
| 配色与可读性 | 文字与浅色条带有足够区分，同级元素颜色一致；参照的是层级与颜色用途，不要求实际色值等于虚构样例。 | 排版流程的取色与颜色映射。 |
| 分页与阅读顺序 | 标题与后续内容保持关联，长段和论文顺序完整，页数符合内容和用户要求；未为固定页数缩字、删事实或隐藏溢出。 | 排版流程的分页；确需精简时返回内容撰写。 |
| 局部保护 | 尽可能同环境渲染前后版本，比较改动及其包围区域、指定保留区域和受影响页面。非预期差异先查底稿、字体和渲染器，再修复本次引入的问题。 | Word 精修的编辑范围定位。 |
| 可用性 | 文本、条带和链接保持要求的可编辑性与行为；结构证据不足时在工作副本中操作验证，不用截图观感替代可编辑性。 | 构建组件或 Word 精修。 |

## 返修与完成条件

1. 定位问题属于事实、组件、布局还是环境，返回对应步骤处理，不同时大改无关区域。
2. 修正后复查该项与受影响内容、对象及页面。分页或全篇字体变化需要重新查看所有受影响页；单个局部改动无需重新开展完整内容研究。
3. 出现相同问题时根据证据调整方案，避免反复运行同一脚本。缺少必要来源、字体、网络或渲染能力时，完成不依赖该条件的部分，明确缺项和未验证范围，不无限循环。
4. 本轮适用项均通过后才称为已验收成稿。仍有不通过或未验证项时，交付可继续编辑的草稿并简要指出具体问题；用户明确接受的例外记录为本轮要求，不静默放宽其他项。

交付清楚命名的新版本及必要的简短说明，除非用户要求覆盖。任务中的事实对应、图标来源、清点报告、真实简历渲染和 QA 工作副本仅用于本次工作，不加入可复用 skill 或公共仓库，也不混入正式简历交付物。构建或更新 skill 时，仅清理本次构建专用的未脱敏副本；用户原始文件与正式输出不在清理范围。
