# 版式规范

这是 GoddessReSUme 的唯一版式依据；流程、组件和验收共同引用。用户指定的风格、纸型及保护区域优先。默认参数是排版起点。新建完整技术简历以充实的一页为默认目标，内容和渲染测量决定框高与位置；用户指定多页、学术长简历或局部保留时按其范围执行。

## 参考资产

[可编辑虚构样例](../assets/layout-reference.docx)与[单页预览](../assets/layout-page-1-e24a7b6a.png)展示本规范：每段教育有两条介绍、项目采用两级分点、正文紧凑排满一页。样例坐标和框数不作为其他经历的固定模板。样例中的身份、机构、经历、论文、日期及示意标识均为虚构，链接采用 example.com，照片为原生占位框。

维护时从空白文档重建，仅提炼字体、配色、尺寸、间距、对齐和对象结构。用户原件、截图、渲染 PDF 或嵌入部件不得加入 skill。预览由新样例重新渲染，文件名随图像内容更新。检查所有 XML、关系、链接、作者元数据、批注修订、隐藏内容、缓存、媒体及缩略图；清理本次构建专用的未脱敏副本，用户原始文件与正式输出不在清理范围。

## 内容单元与对象结构

默认单栏紧凑布局：姓名与联系信息在页首，用户提供的照片在右上；正文由栏目、机构、项目和逻辑段落展开。

| 内容单元 | 对象与关联 |
| --- | --- |
| 姓名、每行联系方式 | 各自一个文本框；同一联系行的图标、文字、分隔符与链接同框。 |
| 可选技术栈 | 联系方式下方独立一行，可用代码图标；长内容应精炼选项或合理换行，避免与照片冲突。 |
| 栏目标题 | 透明标题文本框与主题色细长矩形组成一个原生组，横线随标题移动。 |
| 学校、公司或项目机构条带 | **无文字底色矩形＋独立图片＋透明文字框**组成一个原生组。无可用图标时如实标记缺项；文字与底色仍分层。 |
| 项目小标题与仓库 | 一个透明文本框；标题左对齐，右侧为仓库图标和真实链接，用右对齐制表位保持同一行。没有仓库则只显示标题。 |
| 项目背景、职责、技术、成果 | 每个逻辑段落独立文本框；背景／职责为实心一级，技术实施分项为空心二级，独立主要成果可为一级。标签留在该段。 |
| 教育介绍 | 每段教育默认两条独立框：学术信息、在校活动／荣誉。有资料填入，缺资料显示标签与可编辑空白；不并入抬头组，也不强制项目符号。 |
| 论文题录 | 每篇一个文本框，作者、标题、出版信息及链接可自然换行。 |

自然换行不拆框；不同逻辑条目不能以多个段落或手动换行塞入同一框。装饰及图片可以是独立形状；“逐段文本框”不要求底色包含文字。仅关联需要共同移动的栏目和机构局部对象，不把正文锁进整页或整段经历的大组；表格和截图不能替代要求的原生文字框。

### 栏目与项目的区别

“教育背景”“实习经历”“项目经历”“科研成果”等是栏目，使用正文列等宽粗横线。“某某系统”“某某算法”等项目小标题使用深色加粗文字，不带栏目横线。

横线左右与正文及条带对齐，贴近标题下缘但不穿字。默认用独立填色矩形，无轮廓，不依赖文本框内的段落下边框；原生标题和横线组成可移动的局部组。不能用文字下划线、下划线字符或带下划线空格模拟。

### 机构分层与垂直居中

底色形状没有 `txbxContent`；机构文字框无填色，包含该行字段及真实制表位；图标是组内独立图片，不是文字段落中的行内图片。三者以条带为共同坐标系。

文字框设置垂直居中，上下内边距对称，段前段后为零，行高与字号匹配；图标按自身可见图形独立居中。给图标保留水平位置，字段不得覆盖图片或互相侵入。日期靠右，其他字段按实际宽度设制表位。

`anchor=ctr` 仅证明属性已设置。需渲染确认字形上下留白；必要的光学微调根据字体和实际画面决定，不能对所有字体固定上移同一数值。

## 图标派生配色

先按 [图标流程](icons.md) 获取并核验，再选择全篇唯一主题来源：用户指定主题或经历优先；否则选最新有彩图标的工作经历，没有则选当前或最近教育经历。仍无可用经历彩图标时沿用用户已有主题，再无则使用中性灰。局部修改不重新选择全篇主题。

取有效图形的代表色，忽略透明、白底、抗锯齿边缘和辅助黑字；不从照片或联系方式图标取色。其他品牌图标保持原色与比例。

| 用途 | 颜色关系 |
| --- | --- |
| 栏目文字、横线、论文作者强调 | 可读主题色；过浅时保持色相并加深。 |
| 机构字段、项目标题 | 同主题的深色变体。 |
| 机构底色 | 默认主色 10% 与白色 90% 混合，可在 8–12% 主色之间微调；透明度写法 `alpha=10000` 为 10%。 |
| 正文与链接 | 正文 `#262626`；链接蓝色下划线并有真实目标。 |

样例用 `#2F6FBA` 演示主题、`#265995` 演示深色；这些颜色不是每份简历的固定值。

## 页面与文字参数

| 项目 | 默认值或约束 |
| --- | --- |
| 页面 | 竖向 595.3 × 864.55 pt，约 210 × 305 mm，自定义纸型；用户指定 A4 时按 A4 重排。 |
| 节边距 | 左右 34 pt，上下 28.35 pt；浮动对象坐标另行控制。 |
| 正文列 | 默认 x=34 pt，宽 527.3 pt；随页宽和安全边界改变。 |
| 页底安全边界 | 正文框及实际文字均不得进入下页边距；仅未越过纸边仍不合格。 |
| 中文 | KaiTi（楷体），包括中文标点、标题、正文及中文联系方式。 |
| 西文与数字 | Times New Roman，包括技术名、日期、论文和链接。 |
| 姓名 | 20 pt、黑灰、加粗、左对齐。 |
| 栏目标题 | 14 pt、主题色、加粗。 |
| 栏目横线 | 默认 1.5 pt 粗、与正文列等宽；结合字形下缘调整距离，无大段空隙。 |
| 机构字段 | 11 pt、加粗、主题深色、同一基线；日期右对齐。 |
| 机构条带 | 默认高 26 pt，无轮廓；图标视觉高约 18 pt，保持比例，宽标识按可用空间排。 |
| 项目小标题 | 10.5 pt、加粗、主题深色。 |
| 正文及教育介绍 | 10.5 pt、黑灰；标签加粗，职责可整体加粗；正文通常两端对齐。 |
| 联系信息与技术栈 | 通常 11 pt；较长链接及技术名清单可采用既定 10.5 pt 层级，不能为强塞一行继续缩字。 |
| 论文题录 | 10.5 pt；科研题录按强调层级使用粗体或斜体，作者名用主题色，共同作者标记保留。 |
| 一级编号 | 原生 `w:numPr`；Wingdings `U+F09F`，符号 10.5 pt；左缩进与悬挂均 7.1 pt。 |
| 二级编号 | 原生 `w:numPr`；Courier New 的 `o`（`U+006F`），符号 7.5 pt；左缩进 12.75 pt、悬挂 7.1 pt。 |
| 正文内边距与行距 | 左右通常 0、上下通常 2 pt；1.2 倍行距，段前段后从 0 起。 |
| 条带文字 | 垂直居中、对称内边距；11 pt 单行可从固定 16 pt 行高开始，实际渲染核对。 |

公式保留数学字体，编号和图标字体仅作用于相应字符。宿主空段落的字号与行距不代表正文样式。

## 一页容量与紧凑排版

先为页首、教育抬头与双介绍行、项目背景／职责／技术分项规划一页容量，再组织文案。默认恰好一页，末条**实质正文的可见底边**距页底安全线以 12–28 pt 为目标。只有页数为 1、正文却停在半页或留下明显页尾空白，不能判为“刚好一页”。填写线、照片和装饰底边不能代替实质正文底边。

正文初稿可按宽度与字体保守估高，随后必须用实际渲染测量修正。用每框文字的实际行数、首末墨迹位置和段间距离确定最终框高；`height=41`、`gap=1` 之类的组合本身不能证明紧凑。下一框从收紧后的底部继续排，不能保留一行内容的两三行高空框。

| 距离类型 | 默认起点与最终检查 |
| --- | --- |
| 同项目相邻正文框 | 框外间距 0–1 pt；同级可见文字间距通常 6–10.5 pt，超过 11 pt 时检查空框高、内边距及行距。 |
| 教育抬头与介绍 | 条带后约 1 pt 起排；两条介绍各保留正常单行高度，相邻框间约 0.5 pt，不增加大块空白。 |
| 不同经历或项目 | 约 6–8 pt，按阅读关系与实测文字位置调整。 |
| 不同栏目 | 约 8–12 pt；标题和首条内容保持关联。 |
| 页尾余量 | 实质正文墨迹至安全线 12–28 pt；按当前纸型计算，不改变纸高凑页数。 |

同项目的背景、职责与技术分项都保持紧凑，不通过拉大行距、框高或段间距填满页面。段前段后从零起，避免内边距、段距和外部位置重复留白。图标及条带按原生结构独立对齐，紧凑排版不压缩字号或裁切文字。

- **正文不足**：回到内容流程，用已有依据展开场景、工程约束、方法关系、个人边界及真实交付，删除重复解释；不新增未知行动、指标或荣誉。教育填写位保留正常行高，不无限加长来充数。
- **内容超出**：压缩重复与低价值表述，重新分配各项目篇幅并收紧无效间距，保留事实和核心贡献。默认一页任务不能自动扩成两页。
- **依据确实不足或用户要求全部保留后无法容纳**：标明一页充实目标尚未达到及具体缺口；完成可做部分，不用虚构内容或宣称合格掩盖冲突。用户明确选择的多页方案另行执行。

渲染测量可用 [layout_metrics.py](../scripts/layout_metrics.py)，结构中的框底仅作初估。文字匹配不确定时检查图像，不把 unknown 当作通过。

## 页首、教育介绍与链接

默认电话、邮箱及即时通讯在同一设计行，各自图标在前，使用 `｜` 分隔；个人 Scholar、GitHub 根据宽度安排后续行。用户要求全部单行时，先调整标签、可用宽度或照片位置。**页首个人 GitHub 的分行规则不适用于项目仓库。**

项目仓库归属对应项目小标题，右对齐到正文右边线。优先用简短显示标签，如 `GitHub` 或 `org/repo`，保留完整目标；检查标题与链接是否碰撞，必要时按本轮版式重新安排，不以连续空格或强行缩字对齐。

每段教育由抬头和两条独立介绍组成。硕博学术行通常为“导师 / 研究方向：”，本科通常为“毕业设计 / 指导教师：”，第二行均为“在校活动 / 荣誉：”。已提供信息直接填入对应行；缺失则保留标签和可编辑空白，不能因材料未提供而省略。只有用户明确取消填写位、要求无占位的成品，或局部任务不涉及教育时，才按范围省略；不虚构导师和活动。

技术栈是可选内容单元，位于联系方式之后，以少量已核实的核心语言、框架或基础设施组成中性清单；可配一个代码图标，不要求每个技术名配 logo。

有照片时优先右上，保持比例并避开文字；没有照片时收回槽位，只有明确要求可填写模板才保留原生占位框。联系图标视觉高约 11 pt，与文本基线协调；不搜索候选人照片。

## OOXML 映射

每个可见 run 显式设置中西文字体与字号，包括超链接和条带：

```xml
<w:rFonts w:ascii="Times New Roman" w:hAnsi="Times New Roman" w:eastAsia="KaiTi"/>
<w:sz w:val="21"/>
<w:szCs w:val="21"/>
```

同一 `rPr` 仅保留一个 `rFonts`，去掉冲突的主题字体属性；`szCs` 不能代替 `sz`。读取现有文档时需解析直接格式、样式继承与主题，不能从属性缺失推断字体。

栏目与条带使用 `wp:anchor → wpg:wgp` 的原生局部组，组内形状各有明确角色和唯一 ID。复制组件需保留完整组、坐标变换和关系，不能只提取第一个 `wps:wsp`。构建细节见 [组件接口](construction.md)，局部编辑见 [Word 精修](word-editing.md)。

单位：1 pt = 12700 EMU；字号与文字位置通常以半磅计，段落缩进与制表位以 twip 计。注意原生矩形高度和段落边框使用不同单位。

样式或对象结构变化时，同步更新组件、从空白生成的样例、预览及相应验收。单一真源是本规范，不通过在其他文件附加例外维护不同版本。
