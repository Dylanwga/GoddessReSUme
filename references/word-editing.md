# Word 局部精修与 OOXML 操作

这是 [排版流程](workflow-layout.md) 的技术参考。局部任务在最新版精确修补；整体任务的样式参数取自 [版式规范](style-spec.md)，验证统一见 [验收](acceptance.md)，不在本文件另设一套标准。

## 保留当前编辑状态

先读取本轮输入，不直接运行旧的生成脚本。用户可能在同名输出上改过位置、字体、分组、链接或页数。记录需保留区域；时间戳仅辅助选择底稿，真正影响编辑的版本冲突再核实。

仅加图标、恢复一行或改指定段落时，优先做有明确范围的 OOXML 补丁，保持其他 ZIP 部件不变。高层库重新保存复杂文本框/分组文档可能引入范围外变化，选择能够保留所涉及对象的编辑方式。

保留未涉及的运行级格式，以及有意义的粗斜体、字段、公式、链接、编号、批注和修订状态。整体转换时按目标规范覆盖字体，不能照搬旧 `rPr` 导致目标样式失效。不要为处理方便接受全部修订、删批注或把公式变成图片；修订视图影响内容依据时先明确核对哪一视图。

## 定位与修改对象

- 用原文字、对象名称/ID、相邻标题、页内位置等组合唯一定位；固定“第几个文本框”在用户继续编辑后不可靠。目标不唯一时继续检查，不盲目全局替换。
- 段落分框粒度按 [对象结构](style-spec.md#内容单元与对象结构)。复制时保留段内 runs、完整字符、超链接、原生公式与强调；整体转换再按目标字体映射处理。
- 为新对象设置可解释的名称、唯一 ID、锚点、页内坐标、宽高、内边距与换行方式。不同坐标基准及分组缩放/偏移须分别换算，不能都当页面绝对坐标。
- 保持照片等独立对象和相邻内容的关系。文本框高度、`autoFit` 或没有手动换行，都不能证明文字自然折行后可见。
- 恢复缺失文字时，先从用户指定的内容来源确认，再复用邻近结构插入最新版。仅在腾空间必要时移动邻近对象，不把整页恢复成旧版。

## 兼容分支与关系

- `mc:AlternateContent` 的 DrawingML `Choice` 与 VML `Fallback` 可能各保存一份内容。清点时选一个有效分支，编辑时同步已有兼容分支，避免重复计数或旧版显示过时。
- 图片和超链接的 `rId` 只在所属部件的关系表内有效。复制内容时保留或重建关系，不能直接照搬别的部件中的 ID 或链接目标。
- 新对象 ID 在有效分支内唯一；检查 `docPr`、图片属性与编辑标记，避免复制对象身份。
- 修改现代图形及 VML 替代物后检查相关缓存。只有确认所改形状的 `o:gfxdata` 等缓存过时才按已验证路径移除或重建，不清除未知缓存。
- 不改的 XML 与 ZIP 部件尽量保持原样；关系目标、内容类型与 ZIP 可读取性由验收检查，不能代替页面渲染。

## 图标与联系方式精修

资源来源按 [图标流程](icons.md)。小图标通常嵌为行内对象，与相应文字共同移动；按版式规范或局部邻近元素匹配有效图形高度、基线和间距。透明画布会影响视觉大小，需要裁空白时优先用文档内裁剪，保持标识原形与比例。

复用已有图标样式时替换图片关系、名称和替代文本；保留用户原链接，不把 Scholar 的目标带给 GitHub，也不把官方品牌资源页当成个人主页。发现疑似错误目标时说明，不猜测替换地址。

用户要求单行时保留其分隔符和全部真实目标，可缩短显示标签并调整可用宽度或头像位置；不靠无效链接或缩小正文凑一行。后续用户改回多行或移动了头像，以最新选择为准。

完成后返回 [验收](acceptance.md)，重点核对请求范围、链接关系和同环境前后渲染差异。
