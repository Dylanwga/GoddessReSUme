# 图标获取与嵌入

这是 [排版流程](workflow-layout.md) 的资源获取参考。整体生成简历或用户要求补图标时，图标准备在主题取色之前完成。输入只有经历文字也要执行；无需用户额外逐项说“搜索校徽、下载公司图标”。

## 确定需要什么

- 为每个真实学校、任职机构，以及实际提供了联系信息的平台列一项；重复机构可复用同一文件。GitHub/Scholar 等主页字段需有真实 URL，即时通讯平台可依据用户提供的账号。
- 电话、邮箱、地址使用同一风格的普通线性图标，可用原生矢量图形或可靠图标集；品牌标识使用确认后的官方图形。
- 个人项目没有官方标识时可以不加；开源项目使用其官方项目标识，不把名称中的公司或框架自动变成任职机构。不要为不确定的机构身份选图。
- 不搜索或下载候选人的个人照片来填头像；只使用用户提供的照片。默认省略没有资料的联系字段与头像槽。

## 检索、下载、确认

1. 优先复用用户提供或当前文档内已核实的图标。
2. 对缺项搜索“机构全称 + 官网 / 校徽 / logo / 视觉识别 / brand assets”，进入机构官网、官方品牌资源页或官方代码仓库核对身份；不能只凭搜索结果缩略图选定。通用搜索只发送公开机构名、平台名和图标需求，不提交整份简历或个人联系方式。
3. 从已查看的页面中获取真实下载链接，不编造 URL。例如 GitHub 有 [官方品牌资源页](https://brand.github.com/foundations/logo)。学校优先用正式校徽，不用活动、周年或院系图标代替学校本身；分校与母校身份按材料确认。
4. 下载到本次任务的工作目录，确认返回的是有效图片而非 HTML 错误页。优先清晰的透明 PNG 或 SVG；SVG 必要时保留原始文件并渲染为透明 PNG 以兼容 Word，不能重新绘制或随意改变品牌外形。
5. 打开下载后的文件，检查机构身份、版本、裁切、透明边缘和小尺寸清晰度。校徽通常使用完整图形，横版标识保持纵横比。品牌本身不按主题重新染色。

把确认结果写在任务工作目录的资产清单中：`对象/用途、来源页面、下载地址、本地文件、核验状态、对应内容块`。清单和下载资源随当前任务使用，不把候选人的机构组合、照片或履历写回可复用 skill。

## 嵌入与布局

- 尺寸、位置和基线遵循 [图标参数](style-spec.md#页面与文字参数)；按有效图形而非透明画布判断视觉大小，右侧留间距。
- 使用图片的图标写入实际嵌入关系 `r:embed`，不把远程 URL 当作外链图片；检查文件在 `word/media/` 中，关系指向它且所在位置正确。原生矢量联系图标按可见图形对象核验，无需产生媒体文件；图片总数不能代替逐项对应检查。
- 优先调用 [构建组件](construction.md) 的机构条带/联系方式方法嵌入图标。机构图标使用局部组内独立图片，与底色和透明文字框共同移动，不进入文字段落；联系方式和项目仓库图标与对应文字同行。
- 电话、邮箱、GitHub/Scholar 等已有有效目标时，文字本身也要可点击；不得把图标来源页误当成候选人的主页。
- 完成经历图标获取后，再按 [图标派生配色](style-spec.md#图标派生配色) 选择一个来源建立全篇主题；来源记录供 [验收](acceptance.md) 逐项核对。

## 获取失败时

先尝试官网品牌页、官网静态资源或官方仓库中合理的备选入口。仍因网络或身份不明无法确认时，记录具体缺项，继续完成其余可用部分；保留真实机构文字，不放假 logo、样例“学/企”图形或 emoji 充数。交付说明哪些图标未补齐，不声称全部达标。

不能联网时可复用已经确认的本地图标；缺少可用经历彩图标时暂沿用用户已有主题，否则用中性灰。只有真正无法取得图标时才进入这个分支，不能把“输入没有附图”当作“图标不可用”。
