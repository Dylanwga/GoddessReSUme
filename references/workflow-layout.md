# 排版与格式流程

本流程把内容单元排成可编辑 DOCX。字体、尺寸、颜色、间距和组件参数统一引用 [版式规范](style-spec.md)。新建完整普通技术简历默认充实地排满一页；用户指定的风格、篇幅、最新版文件与保护区域优先，完成后按 [独立验收](acceptance.md) 检查实际产物。

## 1. 读取最新底稿与版式依据

- **新建完整简历**：读取完整 skill、版式规范和脱敏参照，接收内容流程整理的事实及内容单元。默认目标是一页，样例的框数、占位文字和留白不作为新简历的内容量。
- **整体优化已有文件**：读取最新版，识别已有文本框、分组、图片、链接、公式、编号、页眉页脚和修订；复用符合要求的对象，转换需要调整的区域，遵循用户确认的篇幅与保留要求。
- **局部编辑**：定位目标及必要的邻近区域，记录需要保留的内容与样式。按 [Word 精修](word-editing.md) 调整，不能运行旧生成脚本覆盖后续手工修改，也不为追求一页改动保护区域。
- **学术 CV 或用户指定多页**：按对应篇幅安排内容，不套用普通技术简历的一页目标。

用 `scripts/docx_inventory.py` 记录内容与对象基线，按 [工具说明](acceptance.md#只读结构清点) 理解其范围；不能只用高层库的普通段落接口读取浮动文本框文档。有底稿时尽可能在同一环境渲染前后版本，保留与本轮修改相关的对照。

区分内容来源与视觉参照。用户提供 PDF 或截图作为版式依据时，先查看对应区域，确认栏目、抬头、项目标题、横线和留白的关系；不要仅根据文字描述推断对象层级。用户指出 Word 等目标应用的实际显示有问题时，该反馈属于待解决缺陷，不能以另一渲染器的正常截图覆盖结论。

通过环境的依赖发现能力确认编辑工具、目标字体和渲染工具；有 documents 技能时遵循其文档操作、渲染和交付要求。依赖或参考资源缺失时先补齐；无法取得则完成可做部分，明确不能验证的范围，不声称已复现模板。

## 2. 建立内容对象与页面容量预算

依据 [内容流程](workflow-content.md) 建立“内容单元 → 原生对象”的对应关系，先确定层级，再安排坐标：

- 栏目标题与具体项目标题分别识别，不能把栏目装饰套用到每个项目。
- 教育与任职机构行、项目抬头、项目背景、职责、技术分项和成果分别归入所属经历。
- 每段教育默认包含两条独立介绍：学术信息与在校活动 / 荣誉。已知内容填入，缺项保留标签及正常单行填写空间；取消空白或局部修改等例外遵循内容流程，不能因用户没额外要求就漏掉。
- 可选项目技术栈位于页首联系信息之后；项目仓库链接归属于项目标题行，个人主页属于联系方式。

一个自然换行的逻辑段落对应一个文本框。每条独立分项单独成框，不能按视觉行拆框，也不能用多个段落或手动换行把不同条目塞入一框。有意留空的教育介绍单元保留可编辑性，不复制样例中的虚构文字来填空间。

新建完整简历在排坐标前计算一页的可用容量：固定纸张及安全边界，扣除实际页首、栏目、机构条带和教育介绍所需高度，将其余空间按相关性与事实丰富程度分配给各段项目，优先容纳关键技术机制的完整展开。不要预设每项目相同条数或每条固定两行；可以让重点分项占 3–4 行、辅助内容更短，相关句子仍同一逻辑框。向内容流程反馈每段经历的高度或行数预算，先形成可充实一页的内容，再进入实际渲染。不能先按保守大框高顺序堆放，溢出后直接新增页面。

## 3. 准备图标与主题

按 [图标获取](icons.md) 建立实际需要的学校、任职机构、项目和联系平台清单，复用已核实资源，或从官方来源搜索、下载并检查后放入任务工作目录。项目、开源贡献与任职关系分别处理，不从项目所属公司推导候选人的雇主。输入没有附图不等于图标不可取得。

完整排版在取得经历图标后按 [主题规则](style-spec.md#图标派生配色) 选取一个主题来源并记录派生色。局部补图标沿用当前主题，不触发全篇重新取色。原始品牌图形保持比例与颜色，图标的视觉大小依据有效图形区域调整。

只为实际信息分配页首空间：没有照片则收回槽位，没有主页则省略链接；用户要求预留时除外。不搜索候选人照片，不把样例占位头像带入成稿。图片与超链接嵌入当前文档部件关系，不依赖远程加载或复制来源的错误目标。

## 4. 构建可独立编辑的原生组件

新建完整文档使用 [构建组件](construction.md)，局部编辑沿用最新文档中适用的对象并按 [Word 精修](word-editing.md) 调整。具体尺寸与字体取自版式规范，保留公式、运行格式、有效链接、编号、批注和修订；工具保真能力不足时更换编辑方式，不删除未知对象绕过问题。

### 栏目标题

栏目文字使用独立文本框，下面用正文列宽的原生实心矩形作为粗横线，并让两者关联移动。线条的高度、位置和主题色按规范设置，左右与正文边界对齐。横线用于“教育背景”“项目经历”等栏目，默认不加到具体项目小标题下。不要依赖文本下划线或下划线字符模拟粗线，也不要仅凭 XML 中存在段落边框就认定粗线会显示。

### 机构与项目抬头

每条抬头使用三层原生对象：底层浅色矩形、中层透明文字框、前层机构或项目图标。背景和文字必须可分别编辑，图标不放进文字行内撑高行距。文字字段以真实制表位排列，按规范垂直居中；整条形成局部原生组，既能整体移动，也能分别选择子对象。

垂直居中以渲染后的字形位置为准，同时检查文字框高度、上下内边距、段落行距和基线。仅设置垂直居中属性不足以保证视觉居中。分组只覆盖同一抬头，不把该经历的所有段落锁进大组。

### 项目标题与仓库链接

项目标题位于左侧，所属仓库图标及真实链接在同一行右侧，按规范使用真正的对齐机制。链接显示标签可简化，完整目标必须保留；不要用连续空格把链接推向右侧，也不要默认另起一行占用正文高度。字段过长时先调整显示标签和可用宽度，再按本轮要求调整布局，不能与标题重叠或缩小正文掩盖问题。

### 正文、教育介绍与页首

背景、职责、各条技术分项、结果、教育介绍及论文分别建立原生文本框。完整项目的分点按语义映射：**背景和职责使用实心一级（level 0），具体技术实施分项使用空心二级（level 1）**，主要独立结果可使用实心一级；职责正文可整体加粗。使用规范要求的原生编号和对应缩进，不能用字符手打圆点，也不能将技术分项全部排成一级。用户已指定的短条目或局部结构按范围保留。教育介绍不强制加项目符号。

各可见 run 显式设置中西文字体和字号，包括超链接及符号字体的使用范围，不只修改 Normal 样式。

每段教育的两条介绍分别创建对象，即使目前只有标签，也保留正常单行高度和可编辑位置；不能省略、合框，或扩大成大块占位空白。页首按实际姓名、联系方式、可选技术栈和照片安排。联系方式遵循用户指定的同行关系与分隔符，保留图标及有效目标；技术栈有独立可编辑文字，不因加入装饰图标改变原有事实。

## 5. 用渲染结果收紧框高与间距

初次构建可以保守估算自然行数和框高，但这只是避免裁切的起点。首轮渲染后逐块确认实际行数、首末行基线及可见文字上下边缘，按实际内容收紧框高，并重新计算后续块的位置。单行、两行和多行正文不能继续沿用同一个保守大框；框内空余高度必须纳入间距核对。

正文段前段后、框内边距和块间距按同一套规范使用，避免重复计入空隙。按阅读关系控制间距：同一项目内的背景、职责和技术分项保持紧凑，项目之间与栏目之间保留清楚层级。教育填写单元使用正常单行高度，其可填写区域单独标明，不当作意外空白压掉。

间距以相邻段落的**实际文字边缘或基线**测量；记录同级块的可见距离并与规范比较。`gap=1` 或两个框几乎相接不能作为通过证据：如果前框内部还留有多余的一行高度，视觉间距仍然失败。可从渲染 PDF 提取文字坐标辅助测量，并回看页面图像；无法提取时在已知页面比例的图像中测量，不能仅凭锚点或存储框高宣称紧凑。

机构长字段通过列宽、制表位或条带高度调整，日期保持右对齐。栏目与至少一段后续内容同页；项目标题与其背景保持阅读关联。每次框高或内容行数变化后重新排后续位置，检查裁切、重叠与行间距，不能只移动一个框留下新的大空隙。

## 6. 校准一页内容充实度

新建完整普通技术简历在收紧真实间距后，按 [版式规范](style-spec.md) 量取最后一段正文的实际墨迹底边到页面底部安全线的距离，目标为 **12–28 pt**。用实际正文墨迹衡量完成度，不能以空文本框底边、装饰线或页脚冒充正文填满。该目标与正常字体、纸张尺寸、紧凑间距一起满足；页数为一页本身不足以通过。

- **底部剩余空间过大**：回到内容流程，从已有依据展开尚未说明的背景、约束、技术关系、Owner 范围和实际交付，优先充实最有价值的项目，再重新渲染。不能整体拉大块间距、加高机构条带、增加无意义空行或重复改写同一事实来凑满。
- **内容溢出或超过安全边界**：先收紧保守框高和超规范空隙，再合并浅层功能点、删除重复表述并重新分配篇幅，为关键技术段保留深度，最后调整合理的换行与列宽。不能将所有分项一起缩成一句。不能擅自扩为两页、缩字号、修改纸张高度、裁切或隐藏溢出。确实无法在一页保留必要事实时说明冲突，交付状态保留未通过，不自行改变用户目标。
- **事实确实不足以充实一页**：完成可支持的内容和默认教育填写单元，说明还缺哪些具体信息，并标记“一页充实目标未达到”。不要为形式验收制造事实或把稀疏页面报为通过。

用户指定多页、学术 CV，以及需要保留原版面的局部编辑，按已确认范围检查密度与分页，不强制套用一页页尾目标。任何篇幅下都必须解决同级文本框间的过宽可见间距。

## 7. 渲染、核对并移交验收

保存清楚命名的新版本，渲染全部受影响页面；完整生成查看每一页实际图像。检查文字完整、教育两条介绍齐全、栏目粗线可见、抬头分层且字形居中、项目链接同行靠右、正文可见间距符合规范，以及适用时刚好一页且页尾充实。逐行检查中文行首行尾标点、中英文混排和分点续行对齐，换行规则按版式规范设置；禁止手动断行凑版。结构清点、实际文字边缘测量与图像观感分别提供证据，不能互相替代。

若用户报告目标应用显示异常，复核实际应用或对应文件与对象；无法直接检查时保留未验证状态，继续定位可能的兼容原因。出现同一问题时调整组件或定位方式，不反复保存同一方案并宣布已修复。用户确认的最新实际效果优先于较早的生成稿和其他渲染器的预览。

将 DOCX、渲染页面、内容与对象对应关系、实际行数与间距测量、一页页尾距离、图标来源和未解决项交给 [独立验收](acceptance.md)。这些工作记录放在本次任务目录，不加入 skill 或公共仓库，也不混入正式交付文件。验收失败返回对应的内容、组件或布局步骤，修正后重新检查受影响对象及页面。
